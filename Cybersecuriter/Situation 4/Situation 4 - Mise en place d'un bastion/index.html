    Mise en place d'un bastion Guacamole¶

    Informations Générales¶

    Auteur : Louis BISERAY Date : 01/01/2026 Sujet : Installation de Guacamole Apache sur Debian 12

    1 . Introduction¶

    Un bastion Apache Guacamole sert de passerelle d'accès distant sécurisée et centralisée pour accéder à des serveurs ou des postes de travail au sein d'un réseau informatique, sans nécessiter l'installation de logiciel ou de VPN sur le poste client.

    Fonctionnalités principales :

    Accès clientless (HTML5) : tout se passe dans un navigateur web ordinaire (Chrome, Firefox, Edge). Guacamole convertit les flux distants en HTML5 / Canvas.

    Support des protocoles standards : il prend en charge SSH, RDP (Windows), VNC et Telnet.

    Point d'entrée unique & isolé : les serveurs cibles restent isolés dans un réseau privé ou un sous-réseau sécurisé. Seul le serveur Guacamole est exposé (via HTTPS).

    Gestion des accès et permissions : centralisation des comptes utilisateurs, prise en charge de la double authentification (MFA / 2FA) et intégration possible avec un annuaire (LDAP, Active Directory, Keycloak).

    Traçabilité et audit : possibilité d'enregistrer les sessions vidéo des utilisateurs ou de consigner les commandes exécutées.

    2. Les fonctions de Guacamole¶

    Guacamole intègre plusieurs fonctions qui vont permettre de mieux suivre les accès aux serveurs de l'infrastructure.

    • Centralisation et suivi des connexions : Qui, quand, où, combien de temps, depuis où
    • Aucun client lourd à installer : l'Accès s'effectue en mode web grâce au HTML5
    • Authentification multi-facteurs : Via un code TOTP (vu précedement)
    • Authentification SSO, compatible avec SAML, OpenID Connect, CAS ou encore LDAP
    • Enregistrements vidéos des sessions : Quand une connexion est en cours d'utilisation
    • Gestion des autorisations : Par groupes ou par utilisateurs

    Guacamole permet également de réduire la surface d'attaque de l'infrastructure pour ne laisser qu'une seule porte d'entrer unique pour nos connexions distantes.

    3. Installation de Guacamole Apache¶

    Pour commencer, nous allons installer un ensemble de paquets. Certains paquets sont spécifiques à certaines fonctionnalités, comme les connexions RDP par exemple.

    [!note]Cette liste de dépendance est tirer de la documentation de IT-Connect

    apt-get update && apt-get upgrade
apt-get install build-essential libcairo2-dev libjpeg62-turbo-dev libpng-dev libtool-bin uuid-dev libossp-uuid-dev libavcodec-dev libavformat-dev libavutil-dev libswscale-dev freerdp2-dev libpango1.0-dev libssh2-1-dev libtelnet-dev libvncserver-dev libwebsockets-dev libpulse-dev libssl-dev libvorbis-dev libwebp-dev

    La partie "Server" d'Apache Guacamole doit être téléchargée et compilée en local pour s'installer. La dernière version sera utilisée, à savoir la version 1.6.0. 

    cd /tmp
wget https://downloads.apache.org/guacamole/1.6.0/source/guacamole-server-1.6.0.tar.gz

    Une fois le téléchargement terminé, on décompresse l'archive tar.gz et on se positionne dans le répertoire obtenu :

    tar -xzf guacamole-server-1.6.0.tar.gz
cd guacamole-server-1.6.0/

    On exécute la commande ci-dessous pour se préparer à la compilation, ce qui va permettre de vérifier la présence des dépendances :

    sudo ./configure --with-systemd-dir=/etc/systemd/system/

    Avant de passer à la suite, on vérifie la sortie de cette commande. Normalement, les librairies principales et dont nous avons besoin sont sur le statut "yes".

    Si aucune erreur n'est présente, poursuivre avec la compilation du code source de guacamole-server :

    sudo make

    Enfin, on termine par installer le composant Guacamole Server :

    sudo make install

    Cependant il reste encore quelques étapes à effectuer. La commande ci-dessous sert à mettre à jour les liens entre guacamole-server et les librairies (cette commande ne retourne aucun résultat) :

    sudo ldconfig

    Ensuite, on va démarrer le service "guacd" correspondant à Guacamole et activer son démarrage automatique. La première commande sert à prendre en compte le nouveau service.

    sudo systemctl daemon-reload
sudo systemctl enable --now guacd

    Enfin, on vérifie le statut d'Apache Guacamole Server le resultat qui sera attendu est active(running) :

    sudo systemctl status guacd

    Dernière étape avant de passer à la partie client d'Apache Guacamole, on crée l'arborescence pour la configuration d'Apache Guacamole. Cela va donner le répertoire /etc/guacamole avec les sous-répertoires etensions et lib. Nous en aurons besoin par la suite pour mettre en place le stockage des données dans une base de données MariaDB / MySQL.

    sudo mkdir -p /etc/guacamole/{extensions,lib}

    Voici la suite complète et exhaustive de ta documentation en Markdown, croisant et adaptant l'ensemble des informations de la Fiche technique (Guacamole 1.6.0 sur Debian 12) et du tutoriel IT-Connect.

    Elle poursuit exactement là où ton premier prompt s'arrêtait (au titre 4. Installer Guacamole Client), tout en corrigeant la coquille de version (1.5.5 remplacé par 1.6.0) et en intégrant l'ensemble des étapes de déploiement (Tomcat 9, MariaDB/MySQL, connecteurs JDBC, sécurisation du service guacd, HTTPS, et troubleshooting RDP).

    4. Installer Guacamole Client¶

    Le module guacamole-client regroupe l'ensemble des éléments nécessaires au fonctionnement de Guacamole, notamment les bibliothèques principales et les extensions utilisées par l'application[cite: 3]. L'ensemble de ces composants forme l'application web fournissant une interface HTML5 accessible depuis un navigateur.

    Cette application web ne communique pas directement avec les machines distantes : elle s'appuie sur guacd, le service inclus dans guacamole-server, qui agit comme intermédiaire et établit les connexions.

    4.1. Déploiement de Tomcat 9¶

    Pour deployer Tomcat un script est déja fournis prés à l'emploi. Récupérer et exécuter le script de déploiement de Tomcat 9 (deploiement_tomcat9.sh) :

    cd /tmp
bash deploiement_tomcat9.sh

    Afin de valider le bon fonctionnement de Tomcat 9, vérifier le statut du service ainsi que l'écoute sur le port 8080 :

    systemctl status tomcat9

    Le retour doit indiquer le statut active (running).

    4.2. Téléchargement et déploiement de l'archive WAR¶

    Nous procédons ensuite à la récupération de l'application web d'Apache Guacamole depuis le dépôt officiel du projet en version 1.6.0 :

    cd /tmp
wget [https://downloads.apache.org/guacamole/1.6.0/binary/guacamole-1.6.0.war](https://downloads.apache.org/guacamole/1.6.0/binary/guacamole-1.6.0.war)

    Après récupération de l'archive, celle-ci doit être déplacée dans le dossier utilisé par Tomcat 9 pour héberger et déployer automatiquement les applications web :

    mv guacamole-1.6.0.war /var/lib/tomcat9/webapps/guacamole.war

    Relancer les services Tomcat 9 et Guacamole Server pour charger la nouvelle application :

    sudo systemctl restart tomcat9 guacd

    5. Base de données MariaDB pour l'authentification¶

    Par défaut, Guacamole ne conserve pas les utilisateurs ni les connexions de façon persistante en base. Nous allons mettre en place une base de données MariaDB afin d'assurer l'authentification et le stockage de la configuration.

    5.1. Installation de MariaDB et création de la base de données¶

    Installation du serveur MariaDB :

    sudo apt install mariadb-server

    Connexion à la console MariaDB en tant que root :

    sudo mysql -u root

    Création de la base de données guacamole_db et de l'utilisateur dédié guaca_cub (à adapter selon votre politique de sécurité) :

    CREATE DATABASE guacamole_db;
CREATE USER 'guaca_cub'@'localhost' IDENTIFIED BY 'Cub_007';
GRANT SELECT, INSERT, UPDATE, DELETE ON guacamole_db.* TO 'guaca_cub'@'localhost';
FLUSH PRIVILEGES;
EXIT;

    5.2. Installation de l'extension JDBC et du connecteur MySQL¶

    Pour connecter Guacamole à MariaDB/MySQL, il est nécessaire d'installer l'extension JDBC Guacamole ainsi que le connecteur MySQL Java.

    1. Téléchargement et mise en place de l'extension JDBC (version 1.6.0) :
    cd /tmp
wget [https://downloads.apache.org/guacamole/1.6.0/binary/guacamole-auth-jdbc-1.6.0.tar.gz](https://downloads.apache.org/guacamole/1.6.0/binary/guacamole-auth-jdbc-1.6.0.tar.gz)
tar -xzf guacamole-auth-jdbc-1.6.0.tar.gz
sudo mv guacamole-auth-jdbc-1.6.0/mysql/guacamole-auth-jdbc-mysql-1.6.0.jar /etc/guacamole/extensions/
    1. Téléchargement et mise en place du connecteur MySQL Java :
    cd /tmp
wget [https://repo1.maven.org/maven2/com/mysql/mysql-connector-j/9.5.0/mysql-connector-j-9.5.0.jar](https://repo1.maven.org/maven2/com/mysql/mysql-connector-j/9.5.0/mysql-connector-j-9.5.0.jar)
sudo cp mysql-connector-j-9.5.0.jar /etc/guacamole/lib/

    5.3. Initialisation du schéma de la base de données¶

    L'extension JDBC contient les scripts SQL nécessaires à la création de la structure de la base (tables, vues, droits). On injecte ces scripts dans MariaDB :

    cd /tmp/guacamole-auth-jdbc-1.6.0/mysql/schema/
cat *.sql | sudo mysql -u root guacamole_db

    5.4. Configuration des fichiers Guacamole¶

    Configuration de guacamole.properties¶

    Créer et éditer le fichier de configuration principal /etc/guacamole/guacamole.properties afin d'indiquer les identifiants de connexion à la base de données :

    sudo nano /etc/guacamole/guacamole.properties

    Insérer le contenu suivant :

    # Configuration MySQL / MariaDB
mysql-hostname: 127.0.0.1
mysql-port: 3306
mysql-database: guacamole_db
mysql-username: guaca_cub
mysql-password: Cub_007

    Configuration de guacd.conf¶

    Afin de préciser sur quel hôte et quel port le service de liaison guacd doit écouter, éditer /etc/guacamole/guacd.conf :

    sudo nano /etc/guacamole/guacd.conf

    Ajouter la configuration suivante :

    [server]
bind_host = 0.0.0.0
bind_port = 4822

    Redémarrer les services pour appliquer l'ensemble des configurations :

    sudo systemctl restart tomcat9 guacd mariadb

    Vous pouvez dès à présent accéder à l'interface HTTP d'Apache Guacamole via l'URL : http://<Adresse_IP>:8080/guacamole/ (identifiants par défaut : guacadmin / guacadmin).

    6. Sécurisation et Optimisations¶

    6.1. Exécution du service guacd sous un utilisateur dédié¶

    Par défaut, le service guacd s'exécute sous le compte système daemon. Pour des raisons de sécurité et pour éviter des problèmes de permissions lors de la négociation de sécurité de certains protocoles (comme RDP), il est vivement recommandé de créer un utilisateur système dédié nommé guacd.

    1. Création de l'utilisateur système et du répertoire de travail :
    sudo useradd -M -d /var/lib/guacd/ -r -s /sbin/nologin -c "Guacd User" guacd
sudo mkdir -p /var/lib/guacd
sudo chown -R guacd: /var/lib/guacd
    1. Modification de l'unité systemd pour utiliser le nouvel utilisateur :
    sudo sed -i 's/daemon/guacd/' /etc/systemd/system/guacd.service
    1. Rechargement et redémarrage du service :
    sudo systemctl daemon-reload
sudo systemctl restart guacd

    Vérifier que le processus tourne désormais sous l'utilisateur guacd :

    ps aux | grep -v grep | grep guacd

    6.2. Configuration du protocole HTTPS pour Tomcat 9¶

    Afin de sécuriser le flux web entre les clients et le bastion, la mise en place d'un chiffrement SSL/TLS est indispensable.

    1. Création du répertoire SSL et génération d'un certificat auto-signé :
    sudo mkdir -p /etc/ssl/guacamole
sudo openssl req -x509 -nodes -days 365 \
  -newkey rsa:2048 \
  -keyout /etc/ssl/guacamole/guacamole.key \
  -out /etc/ssl/guacamole/guacamole.crt
    1. Ajustement des permissions pour l'utilisateur tomcat :
    sudo chown root:tomcat /etc/ssl/guacamole/guacamole.key
sudo chmod 640 /etc/ssl/guacamole/guacamole.key
sudo chmod 644 /etc/ssl/guacamole/guacamole.crt
    1. Activation du connecteur HTTPS dans Tomcat 9 :

    Éditer le fichier /etc/tomcat9/server.xml :

    sudo nano /etc/tomcat9/server.xml

    Ajouter ou modifier la section du connecteur HTTPS (vers la ligne 90) :

    <Connector SSLEnabled="true" maxThreads="150" port="8443" protocol="org.apache.coyote.http11.Http11NioProtocol">
    <SSLHostConfig>
        <Certificate certificateFile="/etc/ssl/guacamole/guacamole.crt" certificateKeyFile="/etc/ssl/guacamole/guacamole.key"/>
    </SSLHostConfig>
</Connector>
    1. Redémarrage et vérification :
    sudo systemctl restart tomcat9
ss -ltnp | egrep '8080|8443'

    L'accès sécurisé au bastion s'effectue désormais à l'adresse : https://<Adresse_IP>:8443/guacamole.

    7. Dépannage (Troubleshooting)¶

    Échec de négociation de sécurité RDP (Security negotiation failed)¶

    Si lors de l'établissement d'une connexion RDP l'erreur suivante apparaît dans les journaux systemctl status guacd ou /var/log/syslog :

    RDP server closed/refused connection: Security negotiation failed (wrong security type?)

    Causes fréquentes et solutions :

    1. Permissions insuffisantes du service : Vérifiez que guacd s'exécute bien sous l'utilisateur dédié guacd et non sous daemon (voir section 6.1).

    2. Type de sécurité RDP dans la configuration de la connexion : Dans l'interface d'administration Guacamole, dans les paramètres de la connexion RDP concernée, modifiez l'option Mode de sécurité / Security mode :

    3. Par défaut (Any), la négociation peut échouer avec certains serveurs Windows récents.
    4. Forcez le mode sur NLA (Network Level Authentication) ou TLS, puis cochez la case Ignorer le certificat (Ignore server certificate) si le serveur Windows utilise un certificat auto-signé.

    8. Annexe : Détail des dépendances système¶

    Pour référence, voici le rôle détaillé des principales bibliothèques installées lors de la préparation de l'environnement Debian 12 :

    Catégorie Paquet Description / Rôle
    Outils de compilation build-essential, libtool-bin Chaîne de compilation de base (gcc,g++,make, gestionnaires de bibliothèques).
    Graphismes & Rendu libcairo2-dev, libjpeg62-turbo-dev, libpng-dev, libwebp-dev, libpango1.0-dev Rendu graphique 2D, support des images (JPEG, PNG, WebP) et gestion du texte internationalisé.
    Vidéo & Audio libavcodec-dev, libavformat-dev, libavutil-dev, libswscale-dev Encodage/décodage vidéo et traitement multimédia via FFmpeg (utilisé pour les enregistrements de session).
    Identifiants uuid-dev, libossp-uuid-dev Génération d'identifiants uniques standard (UUID) pour les sessions.
    Protocoles d'accès freerdp2-dev, libssh2-1-dev, libtelnet-dev, libvncserver-dev Prise en charge native des protocoles RDP (Windows), SSH, Telnet et VNC.
    Réseau & Sécurité libwebsockets-dev, libssl-dev Communication en temps réel via WebSockets et chiffrement TLS/SSL des flux.
